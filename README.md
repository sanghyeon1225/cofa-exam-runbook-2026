# Cofa Sol 6.1 과제 진행 가이드

Cofa에서 제공하는 Codex와 Sol 6.1로 과제를 시작하고, 공개 준비 키트를 참고해 구현·검증·제출까지 진행하는 순서다. 일반적인 준비 문서이며 실제 시험 문제·답안·데이터는 포함하지 않는다. 실제 과제 안내와 최신 운영 공지를 우선한다.

## 1 이 가이드 받기

Cofa의 일반 Terminal에서 실제 과제 폴더인지 확인한 뒤 실행한다. 일반 Terminal과 Codex의 AI 입력란은 다르다.

```bash
pwd
ls
git clone --depth 1 https://github.com/sanghyeon1225/cofa-exam-runbook-2026.git .cofa-guide
cat .cofa-guide/README.md
```

이미 `.cofa-guide`가 있으면 재다운로드하거나 지우지 말고 기존 파일을 확인한다. 이 가이드는 Cofa 안의 편집기나 제공 Codex로 읽는다.

## 2 공개 키트 받기

같은 과제 폴더의 일반 Terminal에서 실행한다.

```bash
git clone --depth 1 https://github.com/ripplelover/cofa-ready-kit.git .cofa-kit
```

이미 `.cofa-kit`가 있으면 기존 내용을 먼저 확인한다. 과제 작업 위치를 유지하고 키트 폴더 안으로 이동하지 않는다. 스킬 설치기 실행이나 MCP 등록은 기본 흐름에 필요하지 않다. 다운로드가 차단되면 제한을 우회하지 말고 Helper에 확인하며 기본 Codex로 실제 과제를 진행한다.

## 3 제공 Codex 열기

Codex 입력란이 이미 보이면 그대로 사용한다. 일반 Terminal만 보이면 아래를 실행한다.

```bash
codex
```

화면에서 제공 모델이 Sol 6.1인지 확인한다. 이후 한글 요청문은 일반 Terminal이 아니라 Codex의 AI 입력란에 넣는다.

## 4 첫 요청 과제 파악

```text
.cofa-kit/prompts/SCENARIO.md를 읽고 진행해줘.
실제 과제 안내·기존 지침을 우선하고 키트 예제와 구분해줘.

먼저 다음을 짧게 정리해줘.
1) 실제 과제 안내 경로, 목표, 필수 제출물
2) 필수 요구사항별 출처와 검증 방법
3) 실무자에게 확인할, 구현 결과를 바꾸는 질문 최대 3개
4) 가장 먼저 완성할 최소 기능

필요한 스킬만 단계별로 읽고 적용해줘.
실제로 읽거나 실행하지 못했으면 그 사실을 밝혀줘.
```

첫 답에서 실제 과제 안내를 읽었는지 확인한다. `.cofa-kit/README.md`와 합성 예제는 실제 문제가 아니다. 업무 기준은 실무자 에이전트, 화면·제출 사용법은 Helper에 직접 질문한다. README에 이미 답이 있는 질문은 반복하지 않는다.

## 5 실무자 답변 반영과 구현

질문은 본인이 직접 보내고 실제 답변을 Codex에 전달한다. 아래 대괄호 부분은 실제 답변으로 바꾼다. 확인할 질문이 없으면 답변 부분을 생략한다.

```text
실무자 답변: [받은 답변 입력]

이 기준을 반영하고 .cofa-kit/skills/cofa-build/SKILL.md를 적용해줘.
필수 기능이 입력부터 결과까지 동작하도록 구현해줘.
확정된 작업은 실행·검증까지 이어가고,
중요한 선택 이유와 실제 검증 결과를 짧게 기록해줘.
답을 못 받은 기준은 가정으로 구분해줘.
```

질문 답변을 기다리는 동안 확정된 부분은 진행한다. 기존 프로젝트 수정이면 실행법과 기존 동작을 먼저 확인하고 최소 범위로 고친다. 실제 요구에 없는 웹앱·프레임워크·외부 서비스를 추가하지 않는다.

## 6 구현 후 검증

```text
.cofa-kit/skills/cofa-verify/SKILL.md를 적용해줘.
실제 요구사항과 현재 결과물을 대조하고,
정상·오류·경계 사례를 실행해 기대 결과와 비교해줘.
필수 실패를 수정하고 관련 검사를 다시 실행해줘.
미검증·누락은 별도로 알려줘.
```

테스트 종료코드뿐 아니라 실행 개수·실패·skip과 실제 결과를 확인한다. 데이터 계산은 작은 손계산과 대조한다. 웹 화면이 필요한 과제는 본인이 플랫폼 Browser에서 핵심 입력·버튼·결과를 직접 확인하고 관찰한 내용을 Codex에 전달한다. UI 자동 조작을 요청하지 않는다.

## 7 제출 확정 전 문서와 설명 점검

아직 제출을 확정하지 않은 상태에서만 사용한다. 대괄호 부분은 화면에 표시된 실제 남은 시간으로 바꾼다.

```text
남은 시간은 [숫자]분이야. 아직 제출 확정 전이야.
필수 제출물과 실행법을 확인하고 문서를 실제 결과에 맞춰 정리해줘.
필수 실패와 누락을 우선 해결해줘.
내가 설명할 핵심 선택 이유·검증 근거·한계를 짚어줘.
제출은 내가 직접 할게. 확정 후에는 AI 작업을 중단해줘.
```

제출 전에 본인이 설명할 수 있어야 하는 내용은 다음과 같다.

- 어떤 요구사항을 해결했고 무엇을 제외했는가.
- 왜 이 구현 방법을 선택했는가.
- 어떤 입력·명령·실제 결과로 검증했는가.
- AI에게 무엇을 맡기고 무엇을 확인·수정했는가.
- 아직 확인하지 못한 부분은 무엇인가.

## 8 시간 배분과 직접 제출

작업 시간이 180분인 경우의 권장 배분이다. 실제 타이머·전체 종료 시각과 운영 안내를 우선하고 후속 문항·업로드 시간을 남긴다.

| 과제 시작 후 경과 | 집중할 일 |
| --- | --- |
| 0~20분 | 실제 과제와 자료 확인, 핵심 질문 |
| 20~110분 | 필수 기능을 입력부터 결과까지 연결 |
| 110~145분 | 오류·경계 사례와 기존 동작 검증 |
| 145~170분 | 필수 문서·설명·저장 확인 |
| 마지막 10분 | 필수 파일과 저장 상태 확인, 직접 제출 |

제출물 확정 후에는 파일을 고치거나 AI·스킬·MCP 작업을 이어가지 않는다. 후속 서술형은 본인이 AI와 복사·붙여넣기 없이 답한다. 질문과 업로드를 모두 마친 최종 완료 화면까지 확인한다.

## 9 막혔을 때

스킬이 목록에 보이지 않으면 해당 파일을 직접 읽도록 요청한다.

```text
.cofa-kit/skills/cofa-triage/SKILL.md를 직접 읽고,
실제 과제 안내를 기준으로 요구사항과 중요한 질문을 정리해줘.
```

대화가 끊겼다면 제출 확정 전인 경우에만 요청한다.

```text
아직 제출 확정 전이야.
.cofa-kit/prompts/SCENARIO.md와 실제 과제 안내,
현재 파일과 검증 기록을 확인하고 이어가줘.
완료·미검증·실패·다음 작업을 짧게 정리해줘.
이전 작업이 성공했을 것이라고 추정하지 마.
```

키트 실행 도구는 Python 3.10+가 필요하지만 위의 지침 파일 읽기 흐름에는 필요하지 않다. 설치나 연결 문제에 막히면 실제 과제 수행과 검증을 우선한다.

## 10 공개 자료와 프롬프트 사용 범위

이 문서는 시험 전에 공개한 일반 준비 자료다. 공개 자료를 Cofa 안으로 내려받아 참고하는 방식으로 작성했지만, 개별 자료의 반입 승인서를 대신하지 않는다. 사용하는 공개 저장소는 결과 통지 전까지 공개 상태를 유지한다는 운영 안내 요약도 함께 확인한다.

개인 메모장·별도 채팅·종이 메모 열람과 개인 PC에서의 프롬프트 붙여넣기는 허용 여부가 확인되지 않았다. 사전 체험의 Helper에 다음과 같이 확인한다.

> 사전 작성한 프롬프트의 열람·붙여넣기가 가능한가요? 공개 GitHub에서 내려받은 프롬프트 파일은 가능한가요?

시험 중 실제 문제·코드·데이터·결과·접속 정보를 외부 AI나 GitHub로 보내지 않는다. 공개 준비 자료를 가져오는 다운로드와 시험 결과를 외부로 올리는 Git Push를 구분한다.
